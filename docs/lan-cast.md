# 投屏与 PiliPlus 设备配对

播放器只保留一个 **投屏** 按钮。设备面板同时搜索 PiliPlus 和 DLNA 设备，并显示设备类型。普通视频使用原有电视播放地址接口向 DLNA 设备投屏；直播使用当前直播流，能否播放取决于电视支持的格式。

## PiliPlus 之间推送

1. 两台设备安装包含此功能的 PiliPlus，并连接同一局域网。
2. 接收端打开 **设置 → 播放设置 → 局域网推送**，开启 **允许接收局域网推送**，再点击 **开启配对模式**。
3. 发送端在视频或直播页点击 **投屏**，选择接收端。首次输入接收端显示的六位配对码；两端会保存配对关系，断开、退出应用或重启后无需重复配对。配对码两分钟有效，配对成功自动关闭配对模式。
4. 接收端打开正常的视频或直播页，用自己的登录状态和播放器设置获取、播放视频。发送端仍停留在原视频页，本地暂停。原有播放/暂停、进度条、快进后退、音量、倍速及长按倍速操作控制接收端，状态每秒同步。直播不支持进度和倍速。
5. 推送期间，播放器右侧中部显示独立的 **接收端全屏 / 退出接收端全屏** 按钮，与左侧锁定按钮对称。原有本机全屏按钮继续控制本机。投屏时该位置的本机截图按钮隐藏，锁定控件后远程全屏按钮也会隐藏。接收端需更新到支持此命令的版本。
6. 保持连接时，控制端选择另一条在线视频、切换分集或直播间，会直接在同一接收端打开并播放；接收端保持切换前的全屏状态。重新点击投屏也能将当前视频发送到已连接设备，无需先断开。切换失败可重试，已配对关系保留。退出视频页或浏览其他页面时，接收端继续播放；应用内会出现可拖动的 **返回投屏控制** 悬浮按钮，点击返回当前推送视频的正常页面并同步状态，不会重新加载接收端视频。该入口适用于应用仍在运行的情况，应用被系统终止后需重新选择设备。
7. 再次点击 **投屏 → 断开推送（保留配对）**，接收端暂停，悬浮入口消失。接收端自行关闭或切换视频后，发送端结束遥控，避免控制错误的视频。
8. 设置页可取消配对。接收端移除设备后，旧凭据立即失效。配对页面可以关闭，接收服务不依赖该页面；已开启的接收功能会在下次启动应用时恢复。

自动发现会用设备的稳定标识匹配已保存的配对关系，即使 IP 或端口改变也无需重新配对。搜索不到时可手动输入接收设置页的 `IP:端口`。接收端需保持 PiliPlus 在前台或处于系统允许的运行状态；移动系统可能暂停后台应用。

## 网络与播放范围

PiliPlus 自动发现使用 Bonjour/mDNS（`_piliplus._tcp`），DLNA 使用原有 SSDP 发现。请允许本地网络访问及桌面防火墙的入站连接。Linux 的 Bonjour 自动发现需要 Avahi。当前 PiliPlus 连接使用局域网 IPv4，不能跨越访客网络隔离。

PiliPlus 推送传递视频、分集或直播间标识、进度和倍速，不传递媒体直链、账号 Cookie 或登录凭据。接收端的视频权限、清晰度、弹幕和字幕由正常视频页决定。暂不推送本地缓存文件或同步播放列表。接收服务使用局域网 HTTP，配对和控制应在可信的家庭局域网使用。

配对标识与凭据存放在独立的 `lanCastTrust` Hive 存储中，不随通用设置导出。协议版本为 2，与旧版临时连接码、独立播放器实现不兼容，两端都需要更新。

## 开发验证

- `flutter analyze --no-pub --no-fatal-infos`
- `flutter test --no-pub`
- 按项目构建脚本为 Flutter、material_ui、cupertino_ui 应用补丁后构建目标平台。

测试覆盖真实回环 HTTP 的配对、重连、撤销、远端全屏、连接内切换视频/分集/直播、快速连续选择、失败重试和切换中断开，磁盘中的信任记录恢复，原播放器控件的遥控与状态同步，退出后悬浮入口的显示、拖动、返回和重新打开视频页，以及 DLNA 播放顺序和失败处理。Bonjour/SSDP 发现、移动平台后台行为及真实跨设备播放仍需使用两台设备联调。
